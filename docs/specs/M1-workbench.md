## 一、目标

M0 搭好了空的三栏工作台。M1 让它真正能用，并为后面所有里程碑定下统一的“任务 → 对话 → 产物 → 审核”流程：

- 健管师在中间对话区用自然语言下任务，实时看到 AI 的回答和执行步骤，可以随时停止、追问。
- 三种工作模式（问一问、想一想、做一做）行为不同，后端强制区分。
- 输入 `/` 调用技能，输入 `@` 引用客户。
- 技能产生的产物以**草稿**保存在右侧结果区，健管师在审核栏确认后，后端才把状态改为“已审核”。已审核产物的通俗版可以复制文本、导出图片或 PDF，由健管师自己通过微信发给客户（Q1）。
- 搭好技能框架，并做一个示例技能跑通全流程。
- 后端按阈值识别危急指标，阈值在后台的“危急指标设置”版块维护（Q12，见第五节之二）。

**做完能看到什么**（路线图原话）：能和 AI 对话，能调用一个示例技能，产物须审核才能发出。

**不包含**（放到后续里程碑）
- 专家智能体和 `@专家`（M3）。M1 里 `@` 只能引用客户。
- 报告上传、识别和解读（M2）。M1 不做文件上传、截图粘贴和语音输入。
- 在系统内把产物直接发送给客户（客户端在 M6 才有）。M1 只提供复制和导出（Q1）。
- 自动化（定时任务）、微信远程、首页（M8、M10）。
- 健管师自建技能（M15）。

## 二、用户

| 层级 | M1 中能做什么 |
|---|---|
| 健管师 | 唯一的使用者：建任务、对话、调用技能、引用自己的客户、审核自己的产物 |
| 机构管理员 | 看不到本机构健管师的任务和产物，以后做质控功能时再定（Q2） |
| 运营商管理员 | 看不到任何任务、对话和产物（只能看到 M0 已有的用量统计）。在后台查看危急指标阈值，不能修改（Q12） |
| 平台管理员 | 看不到任何任务、对话和产物。维护全平台唯一的一套危急指标阈值（Q12） |
| 客户 | 不参与（M6） |

## 三、交互流程

### 3.1 三栏布局（沿用 M0 的空壳）

- **左侧栏**
  - **新建任务**按钮。
  - **任务列表**：按客户分组（功能清单：“客户即工作空间”）。没有引用客户的任务放在“未关联客户”分组。按最近更新排序。
  - 点任务名可以重命名、归档。只有归档（隐藏），不提供彻底删除（Q3）。列表底部有“已归档”入口，可以查看和取消归档。
  - **技能**入口：列出可用技能（M1 只有示例技能），点击等同于在输入框输入 `/技能名`。
  - 专家中心、自动化：保持占位，显示“即将开放”。
- **中间对话区**
  - 消息流：健管师消息、AI 回答（流式逐字出现）、执行步骤卡片。
  - 输入框带模式切换、`/` 和 `@` 补全、发送和停止按钮。
- **右侧结果区**
  - **产物**标签：当前任务生成的产物，带状态标签（草稿、已审核、已退回、已作废）。点开可以预览和编辑。
  - **客户**标签：当前任务关联客户的基本信息（M0 已有的客户摘要接口）。孪生卡片在 M4 做。
  - **记录**标签：当前产物的修改和审核记录。
  - **审核栏**：固定在产物预览底部，草稿上有“确认”“退回重写”两个按钮；已审核产物上换成“复制通俗版”“导出图片”“导出 PDF”“基于此版修改”。危急指标提示也显示在这里。

手机宽度沿用 M0 的抽屉和底部面板，不横向滚动。

### 3.2 一次对话的过程

1. 健管师新建任务（或在已有任务里继续），选择模式，输入内容并发送。
2. 后端建立流式连接，依次推送：
   - **步骤事件**，如“正在读取客户档案”“正在生成小结”。每一步有开始和完成两个状态，前端显示成可展开的步骤卡片。
   - **文本片段**，前端逐字显示。
   - **产物事件**（仅做一做），表示产物已作为草稿保存，结果区自动打开并定位到它。
   - **技能建议事件**（Q5），AI 判断健管师的话适合用某个技能时推送，前端在回答下方显示“使用 /技能名”按钮。
   - **结束事件**，带完成原因：正常、被停止、被拒答、出错。
3. 健管师可以随时点**停止**。后端中断大模型调用，已生成的文本保留并标记“已停止”，不生成产物。
4. 生成过程中可以继续输入追问。追问在当前回答结束或被停止后才发出，不并行。
5. 刷新页面或切换任务后，再回来能看到完整的历史消息、步骤和产物。

### 3.3 三种模式

| 模式 | 行为 | 后端强制 |
|---|---|---|
| 问一问 | 只回答问题。可以读取被 `@` 客户的档案来回答，但不生成产物。在问一问里选了 `/技能` 时，输入框上方提示“技能需要在做一做或想一想模式下使用”，并提供一键切换到做一做（Q4），不发送 | 本次请求不允许写产物表；带 skillId 的问一问请求返回 400 |
| 想一想 | 先输出一份分步计划（列出要读哪些资料、要生成什么），显示“确认执行”“修改计划”两个按钮。健管师确认后，按计划执行，相当于转入做一做 | 计划确认前不允许写产物表；确认请求必须引用这份计划 |
| 做一做（默认） | 直接执行技能并生成产物草稿 | 产物一律以草稿状态写入 |

M1 中，想一想的计划步骤只包括“读客户档案”和“调用某个技能”两种，因为只有一个示例技能。复杂计划（批量处理、多技能串联）在后续里程碑扩展。

### 3.4 `/` 技能

- 输入 `/` 弹出技能列表，可以继续输入文字过滤，用方向键和回车选择。
- 选中后，输入框里出现一个技能标签。一条消息最多一个技能。
- 技能如果要求必须引用客户，而健管师没有 `@`，前端在发送前提示“请先 @ 客户”，不猜测；后端也拒绝这样的请求（400）。
- M1 只支持显式 `/` 调用（Q5）。不输入 `/`、只用自然语言描述（如“帮我给张阿姨写个近况小结”）时，AI 不自动执行技能，而是在回复里建议使用哪个技能，前端显示一个按钮，健管师点一下就把技能标签放进输入框，再由健管师发送。

### 3.5 `@` 引用客户

- 输入 `@` 弹出**当前健管师自己的客户**列表，按姓名过滤。数据来自 M0 的客户列表接口，后端仍受行级安全约束。
- 选中后插入客户标签。一个任务第一次引用客户时，这个任务就归到该客户分组下。
- 每个任务只关联一位客户，和“客户即工作空间”一致（Q6）。任务已关联客户后再 `@` 别的客户，前端提示“请新建任务”，后端返回 404。批量处理以后单独设计。
- 消息里保存的是客户 id，不是名字。后端处理时重新校验这个客户是否对当前健管师可见，看不到就按“不存在”处理。

### 3.6 产物和审核

产物状态流转（全部在后端校验，前端按钮只是入口）：

```
草稿 ──确认──▶ 已审核 ──基于此版修改──▶ 新的草稿（新版本）
  │  ▲
  │  └──修改（健管师手动编辑，仍是草稿，记一条修改记录）
  ├──退回重写──▶ 已退回 ──（AI 根据退回意见生成新版本）──▶ 新的草稿
  └──客户转出（系统自动）──▶ 已作废
```

- 健管师可以在预览里直接修改草稿文字，保存后仍是草稿。
- 产物分两部分：**专业版**只给健管师看，永远不会进入任何发给客户的通道；**通俗版**是审核后可以给客户的内容。
- 通俗版末尾的免责声明“仅供参考，非医疗诊断”由后端固定拼接，不让模型生成，健管师编辑时也删不掉。
- “确认”时，后端在同一个事务里做以下检查，任何一项不通过都拒绝确认，前端标出问题位置：
  - 通俗版没有禁用词（词表来自 `packages/shared/compliance`，匹配前先去掉空格和零宽字符，统一全角半角）；
  - 通俗版带有标准免责声明；
  - 确认的是这个产物最新的一版草稿，内容和健管师预览时一致（请求带上版本号和内容指纹，别的窗口改过就拒绝）；
  - 通俗版里没有危急指标的数值（危急指标永远不进通俗版）；
  - 通俗版正文不为空，免责声明只出现一次。
- 通俗版里出现疾病名称、“患有”“有……风险”这类判断句式时，审核栏醒目提示健管师。这一项只提示、不拦截，因为最终由健管师判断。
- “退回重写”需要填写退回原因，AI 据此生成一个新版本，旧版本保留在记录里。
- 模型拒答或输出格式不合格时，不生成产物，也不留半成品草稿。
- 已审核的产物不能直接修改，只能“基于此版修改”生成新版本的草稿，新版本要重新审核。旧版本和审核记录都保留，便于追溯（Q7）。
- **发出方式**（Q1）：已审核产物的通俗版可以复制文本、导出图片（PNG）或 PDF，健管师自己通过微信发给客户。
  - 复制和导出的内容都由后端按产物 id 取出，只有已审核产物的通俗版，带免责声明和 Health Buddy 名称，不含专业版、危急指标提示或其他内部信息。草稿、已退回、已作废的产物请求导出返回 409。
  - 图片和 PDF 在后端生成（服务器需要装中文字体），格式统一，健管师改不了版式。文件名用“近况小结-日期”，不带客户姓名。
  - 每次复制和导出都记一条记录（谁、什么时候、什么格式），不记内容。
- **危急指标提示**：后端按阈值识别出的危急指标（第五节之二）显示在审核栏顶部，健管师必须先勾选“已知悉”才能确认，确认记录里记下“已知悉”。危急指标只出现在专业版和审核栏，永远不进通俗版。

## 四、示例技能

M1 的示例技能是 **“客户近况小结”**（Q8），用来跑通“引用客户 → 读档案 → 生成草稿 → 审核 → 复制或导出”的全过程：
- 读取被 `@` 客户最近 30 天的监测数据和最近一份体检报告的结构化指标。M0 的合成数据里已经有这些。
- 生成两部分：给健管师看的**专业版小结**，以及可以发给客户的**通俗版**（带免责声明）。
- 只用 M0 已有的数据，不依赖 M2 的报告识别。正好能检验“涉及健康判断的产物必须审核”。
- 读取的数据先过危急指标识别（第五节之二），结果作为结构化字段放进产物。

## 五、数据模型草案（写进规格，不改代码）

**所有新表**（包括消息、步骤、计划、记录这几张子表）都带 `operator_id`、`org_id`、`manager_id`，并开启行级安全。复合外键保证任务、消息、产物属于同一个健管师和同一位客户：
- 子表用 (task_id, manager_id) → tasks(id, manager_id)，记录表用 (artifact_id, manager_id) → artifacts(id, manager_id)；
- 每张表都有 (manager_id, org_id) → users(id, org_id) on update cascade，健管师调机构时跟着走，和 M0 的客户表一样；
- artifacts 用 (task_id, client_id, manager_id) → tasks 保证和任务一致，parent_id 只能指向同一任务的产物；
- clients 表需要补一个 (id, manager_id) 唯一约束，tasks 才能引用。

| 表 | 主要字段 | 说明 |
|---|---|---|
| `tasks` | id, operator_id, org_id, manager_id, client_id（可空）, title, created_at, updated_at, archived_at（可空） | 一个任务就是一段对话。client_id 通过外键 (client_id, manager_id) → clients 保证只能关联自己的客户 |
| `task_messages` | id, task_id, role（manager / assistant）, mode, content, skill_id（可空）, client_refs, status（streaming / complete / stopped / refused / error）, created_at | 对话消息。content 含健康信息，只存数据库，绝不写日志 |
| `task_steps` | id, message_id, seq, kind, label_key, status（running / done / failed）, started_at, finished_at | 执行步骤。label_key 是 i18n 键，不存自由文本 |
| `task_plans` | id, message_id, steps（JSON）, status（proposed / confirmed / revised） | 想一想模式的计划 |
| `artifacts` | id, task_id, client_id（可空）, manager_id, operator_id, org_id, skill_id, kind, version, parent_id（可空）, status（draft / approved / returned / voided）, content（JSON：professional、client_facing）, critical_flags（JSON，见第五节之二）, created_at | 产物。每次 AI 重写或基于已审核产物修改，都产生新版本 |
| `artifact_events` | id, artifact_id, actor_id（系统操作为空）, action（created / edited / approved / returned / voided / copied / exported）, reason（可空）, format（导出时：png / pdf）, created_at | 修改、审核、复制和导出记录。只记谁在什么时候做了什么，编辑前后的全文不进这张表 |

`tasks` 另加 detached_reason（可空：client_transferred / client_deleted），用于 Q11 的处理。

**行级安全要点**
- 所有新表的策略只放行 `app_role() = 'manager' and manager_id = app_user_id()`。写入时还要检查 operator_id 和 org_id 与当前上下文一致。
- 不能照抄客户表的策略（它对机构管理员开放），也不能用“查 clients 表”来推导可见性。
- 运营商、平台和机构管理员对这几张表都没有读取权限（Q2）。
- 产物状态在数据库层也要锁住：
  - 新插入的产物只能是 draft；
  - 状态只允许 draft → approved、draft → returned、draft → voided 三种变化；
  - approved、returned、voided 的行不能再改（用触发器实现，因为行级安全比较不了改前改后）。唯一例外是客户转出或删除时，由专门的方法把 client_id 置空，触发器只放行这一列从有值变为空。
- `llm_usage` 不增加 task_id 和 client_id，避免运营商和平台通过用量表看到客户明细。
- **客户转出或删除**（Q11），都由专门的方法在同一个事务里处理：
  - 转给别的健管师：原健管师的相关任务自动归档、标记 detached_reason = client_transferred，变成只读（不能再发消息、不能修改、不能确认）；未审核的草稿改为已作废；已审核的产物保留，仍可在记录里查看，但不能再复制或导出给客户。新健管师看不到原来的任务和对话。
  - 客户被删除：任务和产物保留，client_id 置空，detached_reason = client_deleted，任务同样归档、只读，草稿作废。
  - 置空 client_id 后，任务和产物在原健管师的列表里放进“已转出或删除的客户”分组。
- 不提供彻底删除任务的功能（Q3）。保留期限正式上线前再定，M1 不做自动清理。

**流式接口持有租户上下文的方式**
- 生成过程可能持续几分钟，期间不占用数据库事务和连接。
- 收到请求时，把当前用户的租户信息记下来；每次写库（步骤、阶段性保存的文本、产物）都单独开一个短事务。
- 保存产物前，重新确认会话仍然有效、客户仍归当前健管师。
- 停止、确认计划、退回重写这几个接口，都先查一遍任务或产物是否属于当前健管师，查不到返回 404，然后才操作正在进行的生成。
- 后台重写任务执行时，从数据库重新取用户的角色和所属机构，不信任任务参数里的租户信息，也不用数据库所有者账号读档案。

## 五之二、危急指标设置（Q12）

**用途**：后端按阈值识别客户数据里的危急指标，提醒健管师建议客户就医。阈值是医学判断，由运营人员在后台维护，Health Buddy 只提供参照国际标准的默认值。

**谁来设置**（Q12，2026年10月15日确认）：由最高一级的平台运营人员统一设置，全平台只有一套阈值，只有平台管理员能改。协会管理员和机构管理员在后台只能查看，健管师读它来识别危急指标，都不能改。

**设置版块**（apps/admin 的平台总后台；协会后台只显示只读列表）
- 列表显示每条规则：指标、方向（高于或低于）、阈值、单位、级别、是否启用、最后修改人和时间。
- 指标只能从 `packages/shared/health` 的指标目录里选，单位跟目录走，不能自己填单位。
- 级别分两档：**需尽快就医**（红色）和 **建议就医评估**（橙色）。
- 可以新增、修改、停用规则，也可以“恢复为默认值”（恢复成下表的默认阈值）。阈值的合理范围由后端校验（例如收缩压只能填 50–300），防止误填。
- 每次修改记一条记录：谁、什么时候、改前和改后的阈值。阈值不是客户数据，可以记数值。
- 页面顶部固定说明：“默认值参照国际通用标准，仅供参考，请由医学顾问审定。”

**默认阈值**（参照国际通用标准，供运营人员审定）

| 指标 | 规则 | 级别 | 参照 |
|---|---|---|---|
| 收缩压 | ≥ 180 mmHg | 需尽快就医 | 美国心脏协会（ACC/AHA 2017）高血压危象；欧洲（ESC/ESH 2018）同为 180 |
| 舒张压 | ≥ 120 mmHg | 需尽快就医 | ACC/AHA 2017 高血压危象 |
| 收缩压 | < 90 mmHg | 建议就医评估 | 低血压的通用界值 |
| 空腹血糖 | < 3.0 mmol/L | 需尽快就医 | 美国糖尿病协会（ADA）2 级低血糖（< 54 mg/dL） |
| 空腹血糖 | ≥ 16.7 mmol/L | 需尽快就医 | 300 mg/dL，临床常用的高血糖紧急评估界值 |
| 静息心率 | < 40 次/分 或 > 130 次/分 | 需尽快就医 | 医院常用危急值；没有统一的国际标准 |
| 血尿酸 | ≥ 540 μmol/L | 建议就医评估 | 9 mg/dL，常用的考虑治疗界值；尿酸没有国际公认的“危急值” |

心率和尿酸没有国际公认的危急标准，默认值是常用做法，特别请运营人员审定。

**识别规则**
- 技能读档案时，对每个指标取最近一次数值逐条比对，命中的写进产物的 critical_flags：指标、数值、日期、来源、命中的规则和级别，以及当时生效的阈值（留存快照，阈值以后改了也能追溯）。
- 按全平台统一的阈值判断。读阈值走带租户上下文的仓储层。
- 识别结果只给健管师：显示在专业版和审核栏，确认前必须勾选“已知悉”。绝不进通俗版、复制和导出的内容，也不推给客户。
- 问一问模式读取客户档案时同样识别，命中时在回答开头醒目提示。
- 识别出危急指标时，日志只记“命中几条、级别”，不记指标数值。

**数据表**
| 表 | 主要字段 | 说明 |
|---|---|---|
| `critical_thresholds` | id, metric, comparator（gte / gt / lte / lt）, value, level（urgent / attention）, enabled, updated_by, updated_at | 全平台一套。行级安全：平台管理员可读写；协会管理员、机构管理员和健管师只读 |
| `critical_threshold_events` | id, threshold_id, actor_id, action（created / updated / deleted）, before（JSON）, after（JSON）, created_at | 修改记录，由触发器写入，只有平台管理员能看 |

- 所有接口都对跨租户和不属于自己的资源返回 404 `not_found`，包括按别人的 clientId 筛选任务列表。每个接口都要有“跨租户访问被拒绝”的测试。
- `approve` 请求必须带上产物版本号，和当前最新草稿不一致时拒绝。
- 技能只读取任务关联的那位客户（task.client_id）。消息里的 clientRefs 必须为空，或者等于这位客户，否则返回 404。
- SSE 的 error 事件只带错误类别，不带厂商的原始错误信息。
- 发消息、确认计划、退回重写合计每位健管师每分钟最多 20 次，超过返回 429 `too_many_requests`（Q10）。
- 问一问模式带 skillId 返回 400；任务已关联客户时 clientRefs 指向别的客户返回 404（Q4、Q6）。
- 只读任务（客户已转出或删除）上的发消息、修改、确认、导出一律返回 409。

## 七、AI 部分

### 7.1 用到的专家和技能
- **专家**：M1 不用任何专家（M3 才做专家引擎）。
- **技能**：只有一个示例技能（见第四节）。技能框架的定义放在 `packages/skills/<技能名>/`，包含：
  - `skill.md`：用途、输入（是否需要客户）、支持的模式、产物类型、提示词，以及两个合规字段：是否有给客户看的内容（`clientFacing`）、是否涉及健康判断（`involvesHealthJudgment`）；
  - 输出结构的 zod 定义；
  - `evals/`：评测用例。
- 合规规则由框架统一执行，不依赖每个技能自己的提示词：所有产物默认草稿；凡是有通俗版的产物，都要过禁用词检查并由后端拼接免责声明。
- **主智能体**：M1 只负责三件事：按模式分流；问一问时直接回答；做一做和想一想时调用健管师指定的技能。不做多技能规划，也不自动选择技能（除非 Q5 另有决定）。

### 7.2 网关需要补的能力
- M0 网关只支持纯文本流。M1 需要补上**结构化输出**：技能产物按 zod 结构返回，校验不通过时重试一次，再失败就报错。
- 是否需要工具调用（让模型自己决定读哪些档案）：M1 不需要。档案由后端按技能定义预先读好，放进提示词。M3 的专家路由再做工具调用。
- 新增网关用途：`chat`（问一问）和 `skill`（技能执行）沿用 M0 已有的 `chat` 路由，并新增一个 `skill` 路由。两家厂商都要支持，默认用 OpenAI（`gpt-6-astra`）。

### 7.3 提示词要点
- 角色：协助健康管理师的助手。读者是健管师，不是客户。结论是供健管师判断的参考。
- 只依据提供的档案数据，不编造数值。每个引用的数值都注明指标名、日期和来源（监测数据或体检报告）。数据缺失时明确说“没有这项数据”。
- 不给出疾病诊断、不推荐具体药物和剂量。涉及治疗、用药、疑似疾病时，提示健管师建议客户就医或转介医生。
- 遇到疑似急症或危急指标，醒目提示健管师建议客户及时就医。危急指标由后端按规则先识别出来，作为结构化字段放进产物并在审核栏醒目显示，模型的提示只作补充。阈值在后台设置，见第五节之二（Q12）。
- 健管师在对话中转述客户有自伤或轻生念头等心理危机信号时，醒目提示健管师按危机流程处理。这类信号绝不进入通俗版。M1 的提示用通用措辞：“请立即联系客户本人和家属，必要时拨打当地急救电话”。具体心理援助热线列表由 Adrain 提供后再加（Q13）。
- 通俗版（给客户看的部分）：
  - 只描述数据和变化趋势，给生活方式建议，并引导客户“有问题请联系您的健管师”；
  - 不出现疾病名称和患病、风险判断，不出现药物，不对心理状态做评价；
  - 禁用词表从 `packages/shared/compliance` 注入提示词，不手写；
  - 不写免责声明，由后端统一拼接；
  - 语气温和，不制造焦虑。
- 问一问的回答不经过审核，所以固定标注“仅供健管师参考，非医疗诊断，请勿直接转发给客户”。
- 客户信息进入提示词时，去掉姓名和联系方式（电话、微信号、地址、证件号），只保留年龄段（如 60–69 岁）、性别和健康数据，用“该客户”指代（Q9）。脱敏在后端组装提示词时统一做，有单元测试检查提示词里不出现姓名和联系方式。
- 提示词和回答原文只存数据库，不写日志、不写埋点。网关只记录用途、型号、token 数和耗时（M0 已做到）。

### 7.4 边界规则
- 产物一律以草稿保存。只有健管师调用确认接口、后端校验通过后，状态才变成“已审核”。
- 问一问模式下，后端拒绝任何写产物的操作。
- 模型拒答时，前端显示统一提示，不展示厂商的拒答原文。
- 红线规则的优先级高于健管师的指令和退回原因。健管师要求“去掉免责声明”“写上确诊”“加上某药某剂量”时，AI 不照做并说明原因，生成的草稿照常过合规检查。
- 防滥用上限（Q10）：每位健管师每分钟最多 20 次大模型调用（发消息、确认计划、退回重写合计），超过返回 429 `too_many_requests`，前端提示稍后再试。套餐额度在 M7 做。

### 7.5 评测（`pnpm eval`）
M1 建立评测框架，并为示例技能写首批用例。同一套用例可以分别跑 OpenAI 和 Claude。大模型输出有随机性，“通过”定义为每个用例连续跑 N 次全部通过（N 在实现时定，至少 3），两家分别统计。用例覆盖：
- **数据准确**：正常客户、单项异常、多项异常、数据缺失四类合成档案。引用的数值、日期、指标名与档案一致；缺数据时不编造。
- **通俗版合规**：每个用例都跑禁用词检查；用规则加大模型评审检查通俗版里没有疾病名称、风险判断、药物和心理评价；不夹带专业版内容；不出现客户姓名。
- **越界指令**：要求下诊断、推荐药物和剂量、去掉免责声明、通俗版写“确诊”或“可以根治”，以及通过退回原因提出同样要求，都不照做。
- **危急值**：血压、血糖偏高和偏低各至少一例。专业版提示就医，通俗版不出现疾病判断和制造焦虑的措辞。
- **心理危机信号**：健管师转述客户有轻生念头时，醒目提示按危机流程处理。
- **问一问**：诊断、用药类提问不下诊断，提示转介。

## 八、验收标准

1. 健管师登录后能新建任务，在三种模式下对话。回答流式显示，执行步骤可以展开。点停止后生成立即中止，已生成的内容保留。
2. 刷新页面后，任务列表按客户分组，历史消息、步骤和产物完整保留。
3. 输入 `/` 能选到示例技能；输入 `@` 只能选到自己的客户。手动构造其他健管师的客户 id 发给接口，返回 404。
4. 做一做执行示例技能后，结果区出现一份草稿。健管师可以修改、确认、退回重写，每一步都有记录。
5. 跳过前端直接调用接口：
   - 把别人的产物改为已审核，返回 404；
   - 把已审核的产物再修改，被拒绝；
   - 确认已退回的产物、确认旧版本、带过期版本号确认，都被拒绝；
   - 问一问模式下尝试生成产物，被拒绝；
   - 停止、确认计划、退回、修改别人的任务或产物，返回 404，也不影响别人正在进行的生成。
6. 确认时的合规检查：
   - 通俗版含禁用词（包括中间插空格、零宽字符、全角半角混用）时，确认按钮不可用，后端也拒绝；
   - 删掉免责声明后确认，被拒绝；
   - 只有已审核产物的通俗版能复制或导出图片、PDF；草稿、已退回、已作废的产物请求复制或导出返回 409；专业版和危急指标提示没有任何发给客户的入口；
   - 导出的图片和 PDF 带免责声明，文件名不含客户姓名，每次复制和导出都有记录；
   - 已审核产物“基于此版修改”生成新版本草稿，旧版本和审核记录保留。
7. 想一想模式先出计划，未确认前不生成产物；确认后按计划执行。问一问模式选了技能时提示切换模式，后端拒绝带技能的问一问请求。自然语言描述技能意图时，AI 只给出技能建议按钮，不自动执行。
8. 危急指标：
   - 合成档案里收缩压 185、空腹血糖 2.8 等命中默认阈值时，产物的 critical_flags 和审核栏正确显示，未勾选“已知悉”不能确认；
   - 这些提示不出现在通俗版、复制文本和导出文件里；
   - 平台管理员修改阈值后，新生成的产物按新阈值识别，旧产物保留当时的阈值快照；
   - 只有平台管理员能改阈值；协会管理员、机构管理员和健管师只能读；阈值超出合理范围被拒绝；每次修改都有记录。
9. 发给大模型的提示词里没有客户姓名和联系方式（单元测试检查组装好的提示词）。每分钟第 21 次调用返回 429。
10. 客户转给别的健管师后：原健管师的相关任务已归档、只读，草稿已作废且不能确认，已审核产物不能再导出；新健管师看不到这些任务。客户被删除后，任务和产物还在，但不再关联客户。
11. 租户隔离：
   - 协会A的健管师通过任何接口都读不到协会B的任务、消息、产物；
   - 同协会内，健管师之间互相看不到；
   - 运营商、平台和机构管理员读不到任何任务、消息、产物；
   - 以应用角色直接查数据库：六张新表和阈值表在没有上下文、或在其他健管师的上下文下，全部查不到（逐表测试）；
   - 数据库层约束：直接插入已审核的产物、直接修改已审核产物的任意一列，都被拒绝；产物的客户和任务不一致、parent 指向其他任务时，插入失败；
   - 健管师调机构后，新表的 org_id 跟着变；
   - 客户转出或删除后，新健管师读不到原来的任务、消息和产物（逐表测试）；
   - 两个健管师同时生成时互不串流；流结束后回到连接池的连接上没有残留的租户设置；长时间的生成不占用数据库事务；
   - `llm_usage` 里没有客户和任务的 id。
12. 日志、错误信息、SSE 错误事件和埋点里搜不到客户姓名、健康数值、提示词、回答原文或厂商原始错误信息（有自动化测试检查）。
13. 示例技能的评测用例全部通过，OpenAI 和 Claude 各跑一遍（Claude API 开通前先只跑 OpenAI）。
14. 所有新界面文字走 i18n。手机宽度下不横向滚动。
15. 预览环境可以完整走一遍：登录 → `@客户` → `/示例技能` → 草稿 → 修改 → 确认 → 复制和导出；平台总后台能修改危急指标阈值。

## 九、问题和答复（2026年10月15日）

1. **Q1 已审核之后怎么“发出”？** M6 之前客户还没有 App。M1 是只把状态改为“已审核”，还是另外提供复制文本、导出图片或 PDF，让健管师自己通过微信发给客户？
   - 答复：提供复制文本、导出图片或 PDF，让健管师自己通过微信发给客户。
2. **Q2 机构管理员能看本机构健管师的任务和产物吗？** M0 中机构管理员能看本机构的客户档案，但任务对话属于健管师的工作过程。
   - 答复：M1 先不开放，以后做质控功能时再定。
3. **Q3 删除任务是真删除还是隐藏？产物和对话保留多久？**
   - 答复：只做“归档”（隐藏），不提供彻底删除。保留期限等正式上线前再定。
4. **Q4 在问一问模式里输入 `/技能`，怎么处理？**
   - 答复：提示“技能需要在做一做或想一想模式下使用”，并提供一键切换。
5. **Q5 不输入 `/`、只说“帮我给张阿姨写个近况小结”时，AI 要不要自动识别并调用技能？**
   - 答复：M1 只支持显式 /。AI 识别到意图时，回复里建议使用哪个技能，由健管师点一下确认。
6. **Q6 一个任务能引用多位客户吗？**
   - 答复：M1 每个任务只关联一位客户，和“客户即工作空间”一致。批量处理以后单独设计。
7. **Q7 已审核的产物还能改吗？**
   - 答复：不能直接改，只能基于它生成新版本，旧版本和审核记录都保留，便于追溯。
8. **Q8 示例技能选哪个？**
   - 答复：“客户近况小结”（见第四节）。
9. **Q9 发给大模型的内容要不要去掉客户姓名和联系方式？** 之前确认过目前无需考虑隐私法规，但功能清单里有“自动脱敏”。
   - 答复：去掉姓名和联系方式，只保留年龄段、性别和健康数据。
10. **Q10 要不要给每位健管师设调用上限？**
    - 答复：M1 先只做技术性的防滥用上限（每分钟 20 次），套餐额度在 M7 做。
11. **Q11 客户转给别的健管师、或被删除后，原来的任务和产物怎么办？**
    - 答复：原健管师那边的任务自动归档、只读，未审核的草稿作废，不能再确认；新健管师看不到原来的对话。客户被删除时，任务和产物保留但与客户断开关联。
12. **Q12 危急指标的阈值由谁来定？** 比如血压、血糖到多少算“需要尽快就医”。这是医学判断，我不应该自己定。
    - 答复：阈值由运营人员确定。在后台做一个危急指标阈值设置版块，运营人员可以设置血压、血糖、尿酸等各项指标，默认数值参照国际标准设定（见第五节之二）。由哪一级设置：由最高一级的平台运营人员统一设置（2026年10月15日确认），协会不能各自调整。
13. **Q13 遇到心理危机信号时，给健管师的提示怎么写？** 比如要不要列出具体的心理援助热线，热线按哪个国家或地区来列。
    - 答复：M1 先用通用措辞（立即联系客户和家属，必要时拨打当地急救电话），具体热线列表由 Adrain 提供后再加。
